### 현재 구현 상태

#### GPS 기록 (RideRecordContext)
- `startRecording()`: GPS watchPosition 시작, Wake Lock 획득
- `stopRecording()`: GPS 종료, 코스 로컬 저장 + Supabase 동기화, `status = 'finished'`
- `resumeFromCheckpoint()`: 앱 재시작 후 저장된 체크포인트에서 이어달리기
- 30초마다 체크포인트 자동 저장 (`localStorage: 'moto:ride_checkpoint'`)
- `status`: `'idle' | 'riding' | 'finished'`

#### GPS watch 구조 (중요)
- **watch ①** `RideRecordContext.startWatchPosition()` — 경로 선(path) 기록용
  - 옵션: `{ enableHighAccuracy: true, timeout: 10000, maximumAge: 2000 }`
  - 5m(0.005km) 이상 이동 시에만 path에 포인트 추가
- **watch ②** `useGeolocation` — 마커(현재위치 표시)용
  - 옵션: `{ enableHighAccuracy: true, timeout: 15000, maximumAge: 3000 }`
  - 모든 GPS 이벤트마다 position 업데이트
- 두 watch는 **독립적으로 작동** — 타이밍 차이 발생 가능

#### UI 흐름
```
idle 상태
  ↓ ▲ 삼각형 버튼 탭
  팬 메뉴 열림 [바로 시작 | 내비로 시작 | 내비 선택]
  
"내비로 시작" → 드라이브세션 체크 → (근처면) "이어달리기?" 팝업
"바로 시작"  → startRecording() 즉시
"내비 선택"  → NaviSettings 시트

riding 상태
  → ●REC 배지 + 빨간 정지 버튼
  → 정지 버튼 탭 → "기록 중지?" 확인 → stopRecording()

finished 상태
  → "Ride Complete" 시트 (거리, 시간, 평균속도)
  → "내 경로에 저장하기" 버튼 → /my-routes 이동
```

#### 드라이브세션 이어달리기 (MapPage.handleStart)
- "내비로 시작" 누를 때 `loadDriveSession()` 확인
- 드라이브세션 있으면 GPS 위치 체크 (스피너 표시)
- 30km 이내: "설정한 경유지에 도착하지 않았습니다. 이어달리겠습니까?" 팝업
  - [이어 달리기]: `startRecording()` + `moto:startDrive` 이벤트 dispatch
  - [취소하기]: idle 유지
- 30km 초과: 드라이브세션 초기화 후 일반 카운트다운

#### DriveSessionOverlay (계획 경로 구간 안내)
**기록 중일 때만 작동** (`recordStatus === 'riding'`)

상태 머신:
```
countdown → (내비 실행) → naviActive → (GPS 도달 확인) →
  ├─ nextSegment: "다음 경유지로 안내할까요?" [안내하기][취소하기]
  │    └─ 취소하기 → stopConfirm: "기록 중지" [중지][취소]
  └─ notArrived: GPS 미도달 [종료|구간완료|계속주행]
```

#### 내비 연동
- **T맵**: `tmap://route?...` 딥링크, 경유지 최대 5개
- **카카오**: `Kakao.Navi.start()` JS SDK (경유지 최대 3개), 실패 시 `kakaomap://` 폴백
- **아틀란**: `atlan://` (기본)
- 구간 분할: `splitIntoSegments()` — 겹침 없이 분할 (1-5번, 6-10번 등)

#### 카카오맵 표시 (MapDisplay)
- `dapi.kakao.com/v2/maps/sdk.js` 동적 로드
- GPS 경로 선 표시, 현재 위치 마커 (CustomOverlay, 나침반 스타일)
- 마커 위치에 EMA 스무딩 적용 중 (α=0.35) — 버그 원인 참고

#### Wake Lock
- 주행 시작 시 `navigator.wakeLock.request('screen')` 획득
- `visibilitychange` → 페이지 visible 복귀 시 재취득 시도
- **멀티윈도우(분할화면)에서는 visibilitychange 미발생** → 재취득 안됨

## 발견된 버그 목록 (2026-05-23 기준)

### 버그 1 — 경로 선 끝과 위치 마커 비동기화 ⬜ 미수정
**증상**: 경로 선이 먼저 가 있고 마커가 선을 따라가는 모양새. 선 끝에 마커가 있어야 함.

**원인**:
- 경로 선(path)은 `RideRecordContext` GPS watch의 raw 마지막 포인트
- 마커는 `useGeolocation` GPS watch + EMA 스무딩(α=0.35) 적용 위치
- EMA 스무딩이 마커를 실제 위치보다 뒤처지게 만듦. 속도가 빠를수록 차이 커짐
- 두 GPS watch의 타이밍 차이도 영향

**수정 방향**: MapDisplay의 EMA 스무딩 제거. 마커 위치 소스를 경로 선과 통일
- `smoothedPosRef` 로직 제거, `currentPosition`을 그대로 사용
- 또는 path 마지막 점을 마커 위치로 사용해서 소스 통일

---

### 버그 2 — 속도 표시가 실시간이 아닌 평균속도 ⬜ 미수정
**증상**: 80km/h로 달려도 표시는 10km/h, 점차 증가함. 정차 시 조금씩 줄어듦.

**원인**:
- `RideHUD.tsx` 70번 줄: `const speed = distance / (duration / 3600)` = **총 거리 ÷ 총 시간 = 평균속도**
- `pos.coords.speed`(m/s, 현재 실시간 속도)가 이미 Location에 저장되는데 HUD에서 사용 안 함

**수정 방향**:
- `RideRecordContext`에 `currentSpeed: number` 상태 추가
- GPS 콜백에서 `pos.coords.speed * 3.6` (km/h) 업데이트
- `pos.coords.speed`가 null이면 직전 두 포인트로 순간속도 계산 (fallback)
- `RideHUD` props에 `speed` 추가, 평균속도 계산 제거

---

### 버그 3 — 마커 이동이 뚝뚝 끊김 ⬜ 미수정
**증상**: 현재위치 마커가 GPS 업데이트마다 텔레포트처럼 점프. 카카오맵 앱처럼 부드럽게 이동해야 함.

**원인**:
- `CustomOverlay.setPosition(latlng)` 은 애니메이션 없이 즉시 위치 변경
- GPS가 1-2초 간격으로 오면 그 간격마다 점프

**수정 방향**:
- overlay의 wrap DOM element에 CSS `transition: transform 0.8s linear` 적용
- 단, 지도 pan/zoom 중엔 transition 끄기 (위치 어긋남 방지)

---

### 버그 4 — 정지 눌러도 저장 안되고 기록이 안 꺼짐 ⬜ 미수정
**증상**:
- 정지 → 중지 버튼 눌러도 상태가 riding으로 유지됨
- 저장도 안 됨
- 멀티윈도우 + 1시간 이상 주행 후 재현됨
- 3분 이내 단시간 주행에서도 재현된 사례 있음

**원인**:
- `stopRecording()` 내부에서 `saveCourse(rideRecord)` 호출에 **try-catch 없음**
- localStorage 저장 중 예외 발생 시 → `setStatus('finished')` 미실행 → 상태 riding 고착
- GPS watch는 이미 ①번에서 종료됐으므로 이후 정지 버튼을 눌러도 같은 실패 반복
- **courseStorage.ts 코드 확인 필요** (buildGpxXml 버그 or localStorage 용량 초과 가능성)

**stopRecording 실행 순서**:
```
① clearWatch(rideWatchRef)     ← GPS 종료 (성공)
② releaseWakeLock()            ← Wake Lock 해제 (성공)
③ localStorage.removeItem      ← 체크포인트 삭제 (성공)
④ saveCourse(rideRecord)       ← ★ 여기서 throw 가능
⑤ insertMyCourse(...)          ← ④ throw 시 미실행
⑥ setStatus('finished')        ← ④ throw 시 미실행 → 버그 발생
```

**수정 방향**: try-catch-finally로 감싸서 저장 성공 여부와 무관하게 `setStatus('finished')` 보장

---

### 버그 5 — 화면꺼짐 주의 표시 (멀티윈도우 환경) ⬜ 미수정
**증상**: 화면꺼짐 방지 기능이 있어도 "화면 꺼짐 주의" 문구로 바뀜. 버그 4와 연관 있는 것으로 추정.

**원인**:
- 멀티윈도우(분할화면)에서 두 앱이 동시에 화면에 보이는 상태
- 내비/유튜브로 포커스 전환 시 Wake Lock 해제됨 (`release` 이벤트 → "화면 꺼짐 주의" 표시)
- 하지만 `visibilitychange`는 **미발생** (페이지가 여전히 visible 상태)
- 현재 재취득 로직이 `visibilitychange`에만 의존 → 재취득 트리거 없음
- 배터리 절약 모드 등에서도 강제 해제 가능

**수정 방향**:
- Wake Lock `release` 이벤트 발생 시 즉시 재취득 시도 (현재는 상태만 업데이트)
- `visibilitychange` 외에 `focus` 이벤트도 재취득 트리거로 추가
- 재취득 실패 시 재시도 로직 추가

---

### 버그 6 — GPX 저장은 됐다고 표시되나 모의주행 경로 엉망 ⬜ 미수정
**증상**: 저장된 주행경로에 GPX 기록이 됐다고 표시되지만, 모의주행 해보면 가지 않은 길을 그림.

**원인 추정**: 미확인 — courseStorage.ts 및 모의주행 재생 로직 확인 필요
- `buildGpxXml` 포인트 순서/포맷 문제 가능성
- 모의주행에서 GPX 좌표 대신 Valhalla API로 도로 경로를 재계산해서 덮어씌우는 경우

**확인 필요 파일**: `src/lib/courseStorage.ts`, 모의주행 관련 컴포넌트

---

### 버그 7 — 터널 통과 시 경로 제멋대로 ⬜ 미수정
**증상**: 터널에서 GPS 끊길 때 경로가 이상하게 그려짐.

**원인**:
- GPS 신호 유실 시 `watchPosition` 콜백 미실행
- 신호 복구 시 위치가 수백m~수km 점프 → 해당 포인트가 그대로 경로에 추가
- 현재 필터: 5m 이하 무시 (하한)만 있고 **상한(너무 큰 점프) 필터 없음**
- `maximumAge: 2000`으로 오래된 캐시 사용 가능 → 복구 직후 타이밍 어긋남

**수정 방향**:
- 이전 포인트와의 시간(ms) 대비 거리로 순간속도 계산
- 물리적으로 불가능한 속도(예: 300km/h 초과) 포인트 무시
- GPS `accuracy` 수치도 필터 기준에 추가 (예: 50m 이상 오차면 무시)
