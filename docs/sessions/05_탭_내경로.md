### 현재 구현 상태

#### 내 경로 목록 (MyRoutesPage)
- 서버 우선 로드 (로그인 시 Supabase, 미로그인 시 로컬)
- 코스 삭제/수정/공유/영상생성 지원
- 전국 누적 동선 지도 표시 (KoreaRouteMap)
- 요약 통계 (총 기록 수, km, 시간)

#### 경로 작성 (RoutePlanner)
- 지도 탭으로 경유지 추가 (최대 20개)
- **Valhalla API** 도로 경로 계산, 실패 시 직선 fallback
- 장소 검색 (PlaceSearchPanel): 카카오 Places API
- 경유지 목록 (WaypointListSheet): 순서 변경(드래그), 삭제
- 역지오코딩: 경유지 좌표 → 주소명 (retry 로직 포함, 최대 15회 300ms 간격)
- 수정 모드: 기존 코스 경유지만 수정 (새 코스 생성 X)
- 코스 확정 (ConfirmPanel): 제목 입력 + 저장

#### 경로 수정 진입
1. 내 경로 → EditModal → "경유지 수정하기" (PenLine 아이콘)
2. RoutePlanner 로 이동, `location.state.editCourseId` 로 기존 코스 식별
3. 수정 후 "경유지 수정 완료" → 기존 코스 업데이트 (새 글 생성 안 됨)
4. **주의**: `editCourseId`는 `useRef`로 마운트 시점 고정 (pushState 충돌 방지)

#### 주행 시작 (handleDrive)
```ts
const handleDrive = (course: SavedCourse) => {
  const naviType  = loadNaviPref()
  const waypoints = getCourseNavWaypoints(course)  // plannerWaypoints 또는 GPX 샘플링
  const segments  = splitIntoSegments(waypoints, naviType)
  // segments: 겹침 없이 분할 (T맵 max5, 카카오 max5, 아틀란 max4)
  const session = { courseId, courseTitle, naviType, segments, currentSegmentIdx: 0, ... }
  window.dispatchEvent(new CustomEvent('moto:startDrive', { detail: session }))
  // DriveSessionOverlay에서 카운트다운 + 내비 실행
}
```

#### 내비 딥링크 (naviUtils.ts)
- **T맵**: `tmap://route?startx={lng}&starty={lat}&goalx={lng}&goaly={lat}&via1x=...` (경유지 최대 5개)
- **카카오**: `Kakao.Navi.start()` JS SDK (경유지 최대 3개, `viaPoints` 배열)
- **아틀란**: `atlan://` (기본 실행만)
- 좌표: `x=경도(lng)`, `y=위도(lat)` (wgs84)

#### ConfirmPanel 디자인
- 흰색 카드 (`bg-white`), 어두운 텍스트 (`text-gray-900`)
- 상단 주황 그라데이션 라인
- `rounded-t-[2rem]` (32px)
- "메모" 입력 (이전에 "한줄 팁"에서 변경)
- 버튼: [취소] + [내 경로에 저장] (공개/비공개 제거됨)

#### PlannerHeader 디자인
- 프로스티드 글래스: `bg-white/15 backdrop-blur-xl`
- km/포인트 배지: `absolute inset-x-0 flex justify-center` (진짜 화면 중앙)

### 중요 버그 이력
- **pushState vs React Router 충돌**: `editCourseId`를 `useRef`로 마운트 시점 고정
- **geocodeName "주소 불러오는 중" 고착**: Geocoder 미로드 → retry 로직으로 해결
- **카카오 로드뷰 SDK 미로드**: `waitForKakaoPlaces()` 폴링으로 해결
